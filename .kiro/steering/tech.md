Session photos, the pickup step and the result are saved on the booking, so a reload keeps them. `/session` has a demo-controls panel (pickup clock, phone position, jump to step).

## Conventions

**Pure engines.** Pricing, billing, climate (solar share, Green Score), rate selection and plug compatibility are pure, deterministic TypeScript. They import no React, AWS SDK, `fetch`, `Date.now()`, or randomness. Inputs go in as plain values, including timestamps. Invalid input returns a typed error that names the field. It does not throw. The formulas live only in the engines; `features/` composes them and UI code displays the results.

**Rounding and constants.** Use `roundHalfUp` (`engines/money.ts`) for every monetary and mile output (2 dp money, 1 dp miles, 3 dp Green Score). Keep every rate, multiplier, weight, radius, and timeout in `engines/constants.ts`, with placeholders marked. No magic numbers in components.

**Adapters.** Each external API sits behind an adapter in `src/adapters/` that owns its timeout, parsing, and fallback, and returns a typed success or failure. Budgets: EIA 5 s; Mapbox, MBTA, and Open-Meteo 10 s; S3 upload and geolocation 30 s. A failed adapter degrades only its own field. Listings still render.

**Distance and search.** DynamoDB has no radius query. Fetch active listings, then filter on the client before rendering MapLibre markers: today by the visible map bounds, with `haversineDistanceMeters()` for every distance. A radius filter (requirement 2.1) must also use `haversineDistanceMeters()`.

**AWS backend.** CDK v2 TypeScript only, no Amplify in any form (`voltlot-rules.md` §2). Stateful resources (user pool, tables, photo bucket) live in `DwellData` with `RETAIN`; never rename their construct ids, because that replaces the resource. Run `cdk synth` and `cdk diff` before every deploy, and leave the deploy itself to the user, who runs it with their own credentials. Use `grant*()` for IAM. Lambdas take the user id from the JWT `sub` and rerun the engines for anything that costs money; the client's numbers are display only. The browser reads its backend settings from `/config.json`.

**Solar share and Green Score** are shown as estimates, only when sunlight data is available. When Open-Meteo fails, keep any stored score and report "solar data unavailable". The Green Score needs a destination (transit miles); without one it is not shown.

**Security.** Protected routes will require Cognito sign-in; today they redirect on the prototype session only. Every API route sits behind the JWT authorizer, and each handler also checks ownership (driver, host, or listing owner). Never commit tokens or keys. The Mapbox token must be URL-restricted. Any key used from the browser (EIA, Mapbox) is visible in the bundle, so it must be a free-tier or URL-restricted key; the EIA call moves to a Lambda with the key in SSM (task 11.3). Bedrock is called only from a Lambda, never from the browser. The browser never gets AWS credentials. Flag any new endpoint that lacks authentication.

**Testing.** Tests sit next to the file under test and run with Vitest. Adapters are mocked in tests. The design requires fast-check for the two property tests (Host Cost Upper-Bound, Green Score Bounds), at least 100 runs each, tagged with `// Feature: voltlot-mvp, Property N`.

## Provisional values and open technical decisions

Do not harden these into rules. Report them and ask.

- **Rounding vs Property 1 (decided Oct 28, 2026):** `electricity_cost_per_hr` and `late_fee` round up to the cent (`engines/money.ts roundUp`), and Property 1 is stated with `P_eff`. Requirement 3.3 and design.md are amended. Drivers pay at most one cent more per hour and per late fee.
- **Missing car kW:** requirement 3.2 says reject a missing `car_max_AC_kW`. Requirement 1.10 and the design resolve it to the host's `charger_kW`. The engine implements `null` → `charger_kW`; the UI has no way to pick an unknown car yet.
- **Solar size bound:** the host wizard accepts 0 to 50 kW; Property 2's domain is 0 to 25 kW.
- **Tailwind version, router, and UI library:** Tailwind 4 and React Router 7 were chosen because the specs do not name them. A component library is still unspecified; the project has its own `components/ui.tsx` and `components/form.tsx`.
- **TypeScript 7.0.2** is the current `latest` at scaffold time. The specs do not pin a version. Typecheck and build pass with it. If a later tool needs the TypeScript 5 or 6 API, revisit this.
- **Helper name:** use `haversineDistanceMeters` (what `lib/geo.ts` exports; design.md now uses it too).
- **Partial hours and minutes:** bookings are whole hours today. Late minutes round up (`settle` uses `ceil`).
- **Data model in design.md:** the DynamoDB item shapes now carry `plug_type` on profiles and EVSpecs, `right_to_list` on listings, and `hostId` on bookings so the host can read them. The prototype does not store `right_to_list`.
- **Sign-in UI:** the design keeps the app's own sign-up and sign-in pages calling the Cognito API (`USER_PASSWORD_AUTH` over TLS; the password is never stored by the app). Cognito managed login with the authorization-code grant and PKCE keeps passwords off our pages entirely but replaces those pages and the terms checkbox. Not decided.
- **Token storage (decided for the demo):** memory plus `sessionStorage` (`state/backend.ts`). A reload keeps the session; a new tab signs in again. Refresh tokens last 7 days, rotate on every refresh and are revoked on sign-out. Revisit (for example an httpOnly cookie set by a backend) before a public launch.
- **Region (decided Oct 27, 2026):** `us-east-2`, set as `region` in `infra/cdk.json` (`-c region=...` overrides). The account belongs to an AWS Organization whose service control policy denies CloudFormation in every other region tested (us-east-1, us-west-1, us-west-2, ca-central-1, eu-west-1), so the stacks ignore the CLI profile's region. CloudFront certificates (task 11.4) must still be issued in us-east-1, which the SCP may block; check before building hosting with a custom domain. Bedrock (flex) must use a model offered in us-east-2.
- **Sign-up rules (decided Oct 26, 2026):** the form matches the Cognito pool. `src/lib/accountRules.ts` holds the password rule (8+ characters with upper case, lower case, a number and a symbol from Cognito's list) and the US phone parser (10 digits stored, `toE164Us` gives `+1` and the digits for Cognito). The sign-up page, the user pool (`PASSWORD_MIN_LENGTH`) and the post-confirmation trigger all use it. The dev demo password `dwell-demo-2026` predates the rule; it still signs in because sign-in never checks strength, and it goes away with Cognito.
- **Cognito email:** the pool uses Cognito's own sender, which has a small daily quota. Configure SES before real sign-ups.
- **Pickup position is client-reported:** `complete-pickup` rechecks the distance, but a phone can send any coordinates. The pickup photo and host-review flag are the backstop.
- **Availability windows:** the prototype uses `{ id, days: number[] (0 = Mon), start, end }` with whole hours and overnight wrap; the design still says "serialized string".
- **Data sources:** Open EV Data US-model coverage and AC phase are unverified (README §10). A note at the end of the README also mentions the AFDC vehicles API.
- **Permanent geocoding cost:** saved addresses require `permanent=true`, which needs a card on file and bills per request, including each autocomplete request. Alternative if cost matters: temporary results for suggestions, then one permanent lookup on selection. Not implemented; untested against the real API.
- **Zillow and Redfin photos are hotlinked:** the mock listings point at third-party images of real homes. They can change or vanish (the UI falls back to a labeled placeholder), and may not be reusable outside a private demo. The addresses are real homes with invented chargers. Replace with owned photos and fictional addresses before any public demo.
- **Exact pin is public:** markers and search use the host's confirmed pin, so the exact driveway point is visible on the public map even though the address text is hidden. Decide whether to show an approximate point until a booking exists.
- **Real Mapbox not exercised here:** behavior was verified in a browser with a fake `pk.` token and intercepted responses shaped like the documented APIs, not against live Mapbox.
